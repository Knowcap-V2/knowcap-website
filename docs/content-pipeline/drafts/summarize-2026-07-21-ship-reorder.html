The arc

Opened on a Google Analytics tag request (already live, no-op), then a real ask: wire a Google Ads conversion event (a tracking signal telling Google Ads "this visitor became a lead," so ad spend optimizes toward it) into the site's lead forms. Traced the actual submit paths — /beta typeform + the beta-modal/contact-form pair that redirect to /thank-you — and wired both, excluding job applications. PR 135, merged.

First /ship run then surfaced 9 stray uncommitted files sitting in the repo. Triaged each: gitignored Playwright debug logs, discarded a bad yarn.lock format rewrite, shipped 3 unwired landing-page variants as WIP. PR 136, merged. A recap HTML got written at the end of that run — and was left uncommitted, because at the time /ship's order was ship-first-then-recap-last.

A second /ship run had to spend its entire turn just committing that leftover recap file (PR 137) — a whole extra shipping cycle for one stray doc. Hassan caught the pattern from the status-bar "1 unsaved" nag and asked: why does this keep happening, and can /ship be fixed so it doesn't. Diagnosis: /ship's STEP ORDER was the bug — it committed+pushed BEFORE writing the recap, so the recap (written last) never made it into that same commit. Rewrote AV/commands/ship.md and AV/skills/summarize/SKILL.md: new order is interview → do the work → write recap → commit/push, and the recap's save-folder no longer needs asking every time — it now defaults to living inside whichever repo is being shipped. Committed directly to AV (sole-dev repo, push-to-master allowed, no PR needed) at 6042f28.

This very recap is the first one written under the NEW order — proof of the fix: it's about to land in the same commit as itself, not a follow-up run.
